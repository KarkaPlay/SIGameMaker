# Подготовка к индексации

Основной публичный адрес: https://sigamemaker.karkaplay.workers.dev/ — взят из README проекта. Публикация изменений и подтверждение владения сайтом выполняются владельцем отдельно.

## Что подготовлено

- Главная `/` сохраняет стартовое меню; рядом с помощью добавлена обычная ссылка «О редакторе» на `/about/`.
- `/about/` — отдельный лендинг в светлом стиле студии: возможности для новичков и опытных авторов, конструктор, сценарии с медиа, объединение, бесплатность, отсутствие регистрации, локальное хранение и открытый код. Основное содержимое, FAQ и переходы на главную доступны без JavaScript. Небольшой `about.js` добавляет пример выбора вопроса, движение его сценария и плавное открытие/закрытие FAQ; не загружает приложение, не обращается к IndexedDB и не отправляет файлы на сервер. При reduced motion переключение и раскрытие работают без пространственной анимации. Ссылка на редактор постоянно доступна в закреплённой шапке, а также в начале и конце страницы.
- В исходном HTML главной есть краткое описание и ссылка на подробности. При запуске приложения этот начальный экран заменяется обычным меню. Если JavaScript отключён, описание и ссылка остаются доступными.
- Обе страницы имеют собственные title, description, canonical и метаданные Open Graph. На странице «О редакторе» есть JSON-LD SoftwareApplication, соответствующий видимому описанию, включая бесплатность и основные функции. Рейтинги и отзывы не выдумываются.
- `robots.txt` разрешает обход всем роботам, в том числе поисковым AI-роботам, и указывает адрес `sitemap.xml`. Отдельная политика для обучения моделей не задавалась.
- Карта сайта содержит только `/` и `/about/`. Состояния редактора и локальные черновики не являются публичными страницами и не перечисляются. Дата изменения не проставляется автоматически при каждой сборке.
- Корневой `404.html` подготовлен для отсутствующих страниц, с `noindex` и ссылкой на главную. В `wrangler.jsonc` задано `assets.not_found_handling: "404-page"`: при публикации с этой конфигурацией Workers должен отдавать ближайший `404.html` с HTTP 404. Само наличие файла без этой настройки не включает собственную страницу ошибки в Workers. Настройка применяется только после публикации и должна быть проверена на том адресе, куда опубликована версия (production и preview — разные адреса). При отдельной ручной загрузке файлов нужно также проверить конфигурацию статических ресурсов хостинга.
- Проверка 404 — несуществующий путь **внутри действующего домена**, например `/missing-page`. Опечатка в самом домене не попадает в приложение и не может показать нашу страницу. Локальный Python-сервер из `npm start` использует свою стандартную страницу ошибки и не читает настройки Workers; `404.html` на нём можно открыть явно, но это не проверка маршрутизации Cloudflare.
- Скрипт подготовки для Cloudflare проверяет наличие этих файлов и копирует их вместе с приложением. Внешние сервисы и новые зависимости не требуются.

## Подтверждение владения

В `dist/index.html`, внутри `<head>`, добавлены предоставленные владельцем метатеги `google-site-verification` и `yandex-verification`. После сборки и публикации нажать «Подтвердить» в каждом кабинете. Теги не удалять из следующих версий сайта.

Белый экран при открытии sitemap.xml не подтверждает, что файл пустой или некорректный. Проверить исходный код ответа страницы: там должен быть XML с `urlset` и двумя адресами. Если содержимое отсутствует либо вместо XML приходит HTML, проверить опубликованные файлы, HTTP-код и Content-Type ответа. Итог обработки карты смотреть в кабинетах поисковиков.

## Что проверить после публикации

1. Собрать сайт через `Собрать сайт.command` и опубликовать обычным способом.
2. Открыть главную и перейти по ссылке «О редакторе», затем вернуться. Проверить стартовый экран при 1280×720 и 1440×900, также с существующим черновиком. На главной не должна появляться прокрутка из-за новой ссылки.
3. Открыть `/about/` без JavaScript: текст, стили и ссылки должны работать. Страница допускает обычную вертикальную прокрутку; компоновка остаётся десктопной.
4. Проверить, что `/`, `/about/`, `/robots.txt`, `/sitemap.xml` доступны без авторизации и CAPTCHA и возвращают HTTP 200; несуществующий адрес возвращает HTTP 404, а не главное меню с кодом 200.
5. Убедиться, что хостинг не добавляет `X-Robots-Tag: noindex` к публичным страницам и не блокирует Googlebot, YandexBot, Bingbot и OAI-SearchBot. Разрешение в robots.txt само по себе не снимает блокировки Cloudflare.
6. Подтвердить владение сайтом в Google Search Console, Яндекс Вебмастере и Bing Webmaster Tools. Добавить `https://sigamemaker.karkaplay.workers.dev/sitemap.xml`, проверить главную и `/about/` инструментами кабинетов и запросить обход.
7. Следить за статусом индексации и реальными поисковыми показами. Подготовка файлов не подтверждает индексацию, позиции или включение в ответы нейросетей.

При смене домена обновить абсолютные адреса в `dist/index.html`, `dist/about/index.html` (включая JSON-LD), `dist/robots.txt`, `dist/sitemap.xml`, README и этой инструкции. По возможности настроить постоянное перенаправление со старого адреса. Черновики между адресами автоматически не переносятся: предварительно скачать резервный .siq.

## Официальные источники

- [Google: AI features and your website](https://developers.google.com/search/docs/appearance/ai-features) — базовые требования SEO применяются и к AI-поиску, специальные AI-файлы не обязательны.
- [OpenAI: Overview of OpenAI Crawlers](https://developers.openai.com/api/docs/bots) — OAI-SearchBot отвечает за поиск, GPTBot имеет отдельное назначение для обучения.
- [Cloudflare: HTML handling](https://developers.cloudflare.com/workers/static-assets/routing/advanced/html-handling/) — обработка статических HTML-страниц на Workers.
